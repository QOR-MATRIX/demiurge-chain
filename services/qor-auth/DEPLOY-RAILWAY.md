# QOR ID on Railway

QOR ID, its Postgres and its Redis run on Railway (ADR-063): project **`demiurge`**, environment `production`,
region `iad`. This file is the record of how they are set up. Railway has deprecated `railway.json`, so every
setting lives on the service and is written down here instead.

## Services

| Service | Source | Notes |
| --- | --- | --- |
| `Postgres` | Railway's `postgres` template | Password generated by Railway. Volume at `/var/lib/postgresql/data` |
| `Redis` | Railway's `redis` template | Password generated by Railway. Volume at `/data` |
| `qor-auth` | `QOR-MATRIX/demiurge-chain`, branch `main`, root `/services/qor-auth` | Built from `Dockerfile` |

## `qor-auth` settings

Root directory `/services/qor-auth`; Dockerfile `Dockerfile`; healthcheck **`/ready`** (it tests Postgres and
Redis; `/health` answers 200 even with a dead database), timeout 120 s; restart on failure, 3 retries; redeploys
only when `/services/qor-auth/**` changes. The Dockerfile's `CMD` starts it, and it reads Railway's `PORT`.
Migrations run at startup, from inside the binary.

## `qor-auth` variables

| Variable | Value |
| --- | --- |
| `RUN_ENV` | `production` |
| `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` |
| `REDIS_URL` | `${{Redis.REDIS_URL}}` |
| `QOR_AUTH__SERVER__HOST` | `0.0.0.0` |
| `QOR_AUTH__JWT__ISSUER` | `qor-auth-demiurge` |
| `QOR_AUTH__JWT__ACCESS_EXPIRY_SECS` | `900` |
| `QOR_AUTH__JWT__REFRESH_EXPIRY_SECS` | `2592000` |
| `QOR_AUTH__SECURITY__MAX_LOGIN_ATTEMPTS` | `5` |
| `QOR_AUTH__SECURITY__LOCKOUT_DURATION_SECS` | `900` |
| `QOR_AUTH__SECURITY__PASSWORD_MIN_LENGTH` | `12` |
| `QOR_AUTH__CHAIN__SS58_PREFIX` | `42` |
| `QOR_AUTH__DATABASE__MAX_CONNECTIONS` | `10` |
| `RUST_LOG` | `qor_auth=info,tower_http=info` |
| `QOR_AUTH__JWT__ACCESS_SECRET` | **Secret.** At least 32 characters. Pasted in the dashboard by the owner |
| `QOR_AUTH__JWT__REFRESH_SECRET` | **Secret.** Different from the access secret. Pasted in the dashboard by the owner |

**`QOR_AUTH__SERVER__PORT` is deliberately not set**, so Railway's `PORT` is used. **`PASSWORD_MIN_LENGTH` is 12**
because `config/production.toml` carries a weaker 8, and changing that file is the owner's policy decision.

**Email is on (1 October 2026).** `EMAIL_FROM` is `Demiurge-Cloud <noreply@demiurge.cloud>`, `BASE_URL` is
`https://id.qorsync.dev`, and `RESEND_API_KEY` is a secret the owner pasted in the dashboard; the service logs
"Email service configured". `RESEND_WEBHOOK_SECRET` is not set yet, so bounce and complaint reports are refused with
503. `RESEND_API_URL` stays unset.

## Secrets

**A secret is never pasted into a shell, a chat or a document.** It goes in the Railway dashboard, under the
service's Variables tab. Rotating the JWT secrets signs every session out.

## The domain

`id.qorsync.dev` is a custom domain on `qor-auth`. Railway gives the DNS record when the domain is attached; it is
set in Cloudflare, which holds `qorsync.dev`'s DNS (ADR-060). `.dev` is HSTS-preloaded, so the name only opens once
Railway has issued its certificate.

## After a deploy

Read the deploy logs for the migrations, then `https://id.qorsync.dev/ready`.
